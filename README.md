# SiliconHQ for DeepSeek Harness

SiliconHQ（`dsh-sihq`）让你在一个 DSH 聊天里，把同一个软件任务按自己定义的步骤交给不同的 coding agent。你可以让 Claude Code 实现改动，让 DSH 运行项目测试，再让只读 Codex 对照测试结果审查代码。工作流和 Agent 实例保存在当前 DSH profile，进度、报告和人工审批可以回到原聊天查看。

当前插件版本为 **0.14.4**，已在 DSH Desktop 宿主 **0.2.2-rc.5** 上验收。首次安装可从 Desktop 插件页添加构建好的本地包。从源码构建或使用 CLI 安装，请参阅[安装和开发](docs/使用手册.md#安装和开发)。

## 第一次运行

1. 打开关联本地项目的 DSH 聊天，输入 `/sihq` 并回车，选择流程。
2. 核对工作目录、步骤和执行者，在「任务」中填写需求。要沿用刚才讨论的约定，展开「引用上下文」勾选相应消息，再点「开始执行」。
3. 在右侧「当前工作流」看进度、报告和待审批事项。要找以前的运行，在原聊天再次输入 `/sihq`，选择「本会话运行记录」。后台日志和取消操作在 DSH Jobs 中。

初始配置提供两条流程。

| 流程 | 适合什么任务 | 初始执行方式 |
| --- | --- | --- |
| SiliconHQ 开发流程（`siliconhq`） | 从需求开始，交付经过独立审查的改动 | 计划 → 开发 → 独立审查。需要修改时回到开发，修复上限可设为 0、1 或 2 次，默认 2 次。额度用尽且仍需修改时生成反馈并汇总。计划、开发与修复、审查、反馈角色默认用 `spawn`，可分别更换。 |
| 只审查当前 diff（`diff-review`） | 已经写好代码，想审查当前目录内已暂存和未暂存的受跟踪改动 | 冻结启动时的 Git diff，交给 `sihq-codex-readonly` 审查。需要 Git 工作树，以及已安装并登录的 Codex CLI。 |

## 如何创建和调用自己的流程

打开 **插件 → 已安装插件 → dsh-sihq → SiliconHQ 工作流**。点「新建工作流」，选择空白流程或开发与审查预设。也可以复制已有的自定义流程，改名后编辑。保存后，新流程会出现在项目聊天的 `/sihq` 列表中。

| 你想做什么 | 在聊天中输入 |
| --- | --- |
| 运行当前设为默认的流程 | `/sihq workflow "修复配置加载并补测试"` |
| 通过名称运行已保存的流程 | `/sihq run "只审查当前 diff" "检查错误处理"` |
| 用稳定 ID 调用，流程改名后仍可用 | `/sihq workflow --template "diff-review" "检查错误处理"` |
| 查流程 ID、查当前 profile 的后端 | `/sihq workflow templates`、`/sihq providers` |

要取得**自己新建流程的指令**，在该流程的「更多操作 → 查看调用指令」点「复制调用指令」，把示例里的「你的任务」替换成实际需求即可。「设为默认」决定第一条命令运行哪个流程。自定义流程支持编辑、试用草稿、复制和删除。后端离线时仍可保存草稿所做的修改，启动预检会指出需要处理的步骤。内置开发流程可以编辑角色，也可以从开发预设新建一条流程来改步骤。

## 一条流程能表达什么

| 能力 | 如何使用 |
| --- | --- |
| 六种步骤 | **只读分析、计划、开发、独立审查**由所选 Agent 执行。**人工确认**由人批准、拒绝或退回。**运行验证命令**由当前会话的 DSH shell 执行，填写可执行文件、逐项参数和超时。 |
| 步骤顺序、并行和分支 | 可以插入、移动、删除步骤，指定输入来自哪些上游报告。相邻且互不依赖的只读步骤可并行，开发步骤串行。后续步骤可按开发、审查或验证报告里的某一结果执行。 |
| 审查和返工 | 默认严格验收。也可选「按阻塞级别验收」，有证据的 P0/P1 缺陷或失败的验收项要求修改，仅有 P2/P3 建议时可通过并保留建议。缺少必要验证证据时可判为受阻。审查或验证可退回指定开发步骤，受修复预算约束。 |
| 上下文和执行说明 | 启动或续轮时可选聊天片段、已有步骤报告、项目 Markdown 和 Git diff。项目文档可按文件名查找。有 `RULES.md` 且宿主已安装 Hypo-Workflow 的 `hw` 时，还可按需求关键词查找。可单独让审查步骤在执行时读取最新 diff。编辑器的「查看 Agent 输入与输出要求」展示步骤说明怎样与任务、上游报告、输出格式组合；运行后可以核对实际派发的内容。 |
| 跨 profile 复用 | 导出 `*.sihq.json`，带走流程和它引用的命名实例。导入时映射本地后端或复用已有实例。凭证由目标 profile 或外部产品管理。 |

例如，在 Node.js 项目中，可以建一条「开发 → 运行验证命令 → 独立审查」流程。验证程序填 `node`，添加一个参数 `--test`。在审查步骤把验证步骤勾为「输入报告」，并启用「执行本步骤时读取最新 Git diff」。这样审查员能同时看到测试输出和开发刚写下的改动。需要测试失败后自动返工时，在验证步骤选定退回的开发步骤并设置次数。[自定义工作流](docs/使用手册.md#自定义工作流)

## 每一步能用哪些 Agent

在「管理 Agent 实例」中，**已注册的基础后端**列出当前 DSH 可调用的执行者。**我的命名实例**列出你为这些后端保存的配置，首次使用时可以为空。同一后端可以建成「快速开发」和「深入开发」两个实例，分别设置模型和思考强度，再在步骤的「执行者」下拉框中选择。实例可增删改查，删除被引用的实例时可统一替换引用。

| 后端 | 适用步骤与配置 |
| --- | --- |
| DSH `spawn` | 可承担全部 Agent 步骤。支持 DSH 模型供应商、模型和思考强度。开发实例可选宿主 Agent 预设，只读步骤使用 `sihq-readonly` 预设。 |
| DSH `fork` | 可用于开发与修复，继承父会话已完成的历史和父预设，可配置模型和思考强度。 |
| 官方 Codex（`codex`）、Claude Code（`claude-code`） | 启用对应的 DSH provider 后可用于开发与修复。可以用命名实例覆盖该次委派的模型和思考强度，登录状态和写入权限沿用基础 provider。 |
| `sihq-codex-readonly` | 用本机 Codex CLI 的只读沙箱执行分析、计划或审查，可选择模型和思考强度。 |
| 其他已注册 provider（含 ACP） | 可用步骤、预设和模型选项取决于该后端声明的能力。使用社区 Product Subagents 0.4.1 时，若聊天已切换工作目录，插件会在派发开发步骤前提示你到目标目录新建聊天。 |

每次启动会保存步骤、执行者和显式模型设置。编辑实例后，新启动的流程采用新配置，已有运行在恢复或续轮时沿用原来的指派。模型或强度留空时沿用相应后端的默认值。实例的「检查配置」核对注册和路由。「实际委派测试」会发起一次模型调用。运行详情分别展示指派给谁，以及宿主或产品实际回报的模型。[Agent 实例与权限](docs/使用手册.md#agent-实例)

## 中断以后怎么继续

| 当前情况 | 操作与结果 |
| --- | --- |
| 启动预检失败、预览过期，或目录与后端配置已变 | 在原弹窗点「重新检查」。保留任务文字，重新载入目录和执行者，再核对本轮引用。 |
| 运行中断，想从已有进度接着做 | 在原聊天点「恢复运行」或输入 `/sihq workflow resume <流程 ID>`。插件优先复用已保存的结果。 |
| 某次尝试失败，想重新执行或换人 | 先核对工作树，再点「重试」或「改派失败步骤」。改派会列出兼容实例和其他实例不可选的原因。原尝试的输入、错误和报告保留供查看。 |
| 本轮结束，想追加需求 | 点「继续下一轮」。旧轮次可回看，新轮次可另选引用。内置流程还可勾选让各角色继承自己的上轮报告。 |

验证报告保留退出码、标准输出和标准错误。程序实际以非零码退出，才会触发为验证失败配置的返工。若出现 `SANDBOX_PREPARATION_FAILED`，详情会说明宿主沙箱准备失败、验证命令未启动。取消后台验证后，如果宿主尚未确认命令退出，插件会阻止重叠工作区的新写入，重启后仍会核对停止记录。纯只读流程可在同一工作区并行，含开发或验证命令的流程需要独占工作区。部分历史数据库暂时被占用时，仍可浏览其余可读记录。[运行命令与恢复](docs/使用手册.md#命令)

## 原 SiliconHQ 的兼容入口

`/sihq run "任务"`（只有一个任务参数）调用原 SiliconHQ 的单任务 CLI。原有的计划、实现、审查、按 ID 恢复，以及有预算的 GPU kernel 优化也保留 CLI 入口，使用 SiliconHQ 自身的 Codex 配置。持久交互聊天和持续跟踪日志在终端使用。GPU 实验需要相应的 Linux/CUDA 环境。[兼容入口](docs/使用手册.md#兼容入口) · [上游 CLI 手册](UPSTREAM.md)
