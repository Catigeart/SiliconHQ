# SiliconHQ for DeepSeek Harness

在关联本地项目的 DSH 聊天里输入 `/sihq` 并回车。选择工作流，核对当前工作目录、步骤和执行者。启动前检查会指出哪个步骤缺少后端、权限或所需的 Git 工作树。填入任务后点击「开始执行」。本次运行使用预览中确认的工作目录和流程配置。

如果任务是「按刚才讨论的方案做」，在启动窗口展开「引用上下文」，勾选包含约定的聊天文字。启动后，右侧的「当前工作流」会显示正在执行的步骤、项目验证的退出码和待处理的审批。刷新后会回到同一流程和所选轮次。展开步骤可核对当时指派的实例、可查到的实际模型、委派输入和报告。要找其他运行，在原聊天输入 `/sihq`，选择「本会话运行记录」。后台日志和取消操作在 DSH 的 Jobs 中。

取消项目验证后，SiliconHQ 会在原会话中核对 DSH shell 报告的命令结束记录。如果宿主强制结束了任务记录，命令退出仍待确认，重试和新的写入会被阻止。重启或恢复旧流程文件后，这项检查仍然有效。已确认命令退出的流程可以在原聊天恢复。

若需求已写进 README 或项目规范，启动时展开「引用上下文 → 项目文档」，浏览目录或按文件名搜索，选择要交给本轮 Agent 的 Markdown 并核对原文。已接入 Hypo-Workflow 的项目还可以按功能关键词查找需求。

在插件设置的「SiliconHQ 工作流」点击「新建工作流」，或从已有的自定义流程复制。例如，把「开发」「运行验证命令」「独立审查」依次排好，为开发和审查各选一个 Agent，在中间步骤填写项目的测试程序和参数。命令正常退出且退出码为 0，才会进入审查。在审查步骤勾选验证结果作为「输入报告」，启用「执行本步骤时读取最新 Git diff」，审查员就能对照测试输出和刚完成的改动。需要由人决定是否继续时，可以插入「人工确认」。

在「独立审查」步骤的「审查策略」选择「按阻塞级别验收」后，P0/P1 缺陷或失败的验收会触发修改，P2/P3 建议保存在右侧运行详情。缺少必要验证时会显示受阻。内置流程可在编辑页设置同一策略，原有流程默认严格验收。

在「管理 Agent 实例」中，可为同一后端保存多套模型和思考强度，供步骤复用。从实例的「更多操作 → 检查配置」核对注册和路由。需要验证账号是否能实际使用模型时，再点「实际委派测试」，这会发起一次模型调用。保存流程后，在工作流的「更多操作」中查看调用指令。

工作流引用的后端离线时仍可编辑和保存，启动窗口会列出尚未就绪的步骤。展开「查看调用指令」可以复制该流程的聊天命令。编辑步骤时，切换类型会更新默认执行说明，自己填写的文字会保留。点击「插入说明示例」可追加文字，展开「查看 Agent 输入与输出要求」可核对实际效果。

```text
/sihq workflow --template diff-review "核对端口变更"
```

在列表的「更多操作」中点击「设为默认」后，`/sihq workflow "任务"` 使用该流程。已有模板 ID 指令继续可用。

想在另一台机器或另一个 profile 复用这套配置，可从该流程的「更多操作」选择「导出工作流」。在目标 profile 点击「导入工作流」，将源后端映射到本地已注册的后端，再确认导入。
